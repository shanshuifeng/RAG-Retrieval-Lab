# 02 · 需求规格说明书

> **文档版本**：v1.0 ｜ **创建日期**：2026-10-16

---

## 一、功能需求

### FR-1 数据模块

| ID | 需求 | 优先级 | 验收标准 |
|---|---|---|---|
| **FR-1.1** | 下载 DuReader-retrieval 数据集 | ⭐ 必须 | 脚本一键完成，含重试机制 |
| **FR-1.2** | 转换为统一 JSONL 格式 | ⭐ 必须 | 通过格式校验 |
| **FR-1.3** | 数据集统计分析 | ⭐ 必须 | 产出统计 JSON（含段落数、query 数等） |
| **FR-1.4** | 支持多种分块策略 | 必须 | 至少 5 种（对应 E4） |
| **FR-1.5** | 支持语料库规模裁剪 | ⭐ 必须 | 可配置（1万/10万/100万） |

### FR-2 检索模块

| ID | 需求 | 优先级 | 验收标准 |
|---|---|---|---|
| **FR-2.1** | BM25 稀疏检索 | ⭐ 必须 | 支持 k1/b 调参 |
| **FR-2.2** | 稠密向量检索 | ⭐ 必须 | FAISS 索引 + 余弦相似度 |
| **FR-2.3** | RRF 混合融合 | 必须 | 支持多检索器融合、k 可调 |
| **FR-2.4** | 统一的检索器接口 | ⭐ 必须 | 抽象基类，可互换 |
| **FR-2.5** | Cross-encoder 重排序 | 必须 | 支持可配置的候选数 |
| **FR-2.6** | 索引持久化 | 必须 | 建一次可复用，避免重复计算 |

### FR-3 评测模块

| ID | 需求 | 优先级 | 验收标准 |
|---|---|---|---|
| **FR-3.1** | Recall@K 计算 | ⭐ 必须 | **有单元测试** |
| **FR-3.2** | MRR@K 计算 | ⭐ 必须 | 有单元测试 |
| **FR-3.3** | nDCG@K 计算 | ⭐ 必须 | ⭐ **有单元测试 + DCG≤IDCG 断言** |
| **FR-3.4** | 多 K 值批量评测 | 必须 | 一次输出多个 K 的指标 |
| **FR-3.5** | 显著性检验 | ⭐ 加分 | 配对 t 检验 / bootstrap |
| **FR-3.6** | 结果导出 | ⭐ 必须 | JSON + CSV，含完整配置 |

### FR-4 实验编排

| ID | 需求 | 优先级 | 验收标准 |
|---|---|---|---|
| **FR-4.1** | 配置驱动的实验 | ⭐ 必须 | YAML 控制，代码不改 |
| **FR-4.2** | 一键运行单个实验 | 必须 | `python -m src.pipeline.run_experiment --config xxx.yaml` |
| **FR-4.3** | 断点续跑 | 加分 | 长任务中断后可继续 |
| **FR-4.4** | 日志记录 | 必须 | 输出到 `logs/`，含耗时 |

### FR-5 报告与可视化

| ID | 需求 | 优先级 | 验收标准 |
|---|---|---|---|
| **FR-5.1** | 结果汇总表 | ⭐ 必须 | 一张表看全部实验 |
| **FR-5.2** | 关键图表 | 必须 | Recall@K 曲线、成本-效果散点 |
| **FR-5.3** | 自动生成报告骨架 | 加分 | Markdown，含数据占位 |

## 二、非功能需求

### NFR-1 性能

| ID | 需求 | 指标 |
|---|---|---|
| **NFR-1.1** | 单次检索延迟 | BM25 < 50ms；稠密 < 100ms |
| **NFR-1.2** | 全量评测耗时 | 2000 query < 60 分钟 |
| **NFR-1.3** | 内存占用 | < 16 GB |
| **NFR-1.4** | 显存占用 | < 8 GB（RTX 4060） |

### NFR-2 可复现性 ⭐

| ID | 需求 |
|---|---|
| **NFR-2.1** | ⭐ **固定随机种子**，同配置跑两次结果一致 |
| **NFR-2.2** | ⭐ **记录完整配置**，包含语料库规模 |
| **NFR-2.3** | 记录环境版本（Python + 关键库） |

### NFR-3 可维护性

| ID | 需求 |
|---|---|
| **NFR-3.1** | 模块解耦，检索器可插拔 |
| **NFR-3.2** | ⭐ **核心指标有单元测试** |
| **NFR-3.3** | 类型标注 + 文档字符串 |

### NFR-4 ⭐ 可解释性（本项目核心）

| ID | 需求 |
|---|---|
| **NFR-4.1** | ⭐ **每个实验必须能回答"提升来自哪里"** |
| **NFR-4.2** | ⭐ **必须报告成本（延迟/显存）** |
| **NFR-4.3** | ⭐ **必须报告基线** |

### NFR-5 合规

| ID | 需求 |
|---|---|
| **NFR-5.1** | 数据集仅用于学术研究，引用原论文 |
| **NFR-5.2** | 不将数据用于商业用途 |
| **NFR-5.3** | 遵守数据集许可条款 |

## 三、⭐ 用户故事

```
【US-1】作为研究者，我想快速得到基线数字，
        以便知道我的评测脚本是否正确。
    → 支持：E1 实验 + 与文献对照

【US-2】作为工程师，我想知道"加个重排序值不值"，
        以便做技术选型决策。
    → 支持：E3 实验 + 成本-效果对比

【US-3】作为学习者，我想理解 RAG 每层的作用，
        以便真正掌握而不是"调包"。
    → 支持：完整消融 + 手写核心逻辑

【US-4】作为未来的我，我想六个月后能复现今天的实验，
        以便验证或改进。
    → 支持：配置记录 + 环境记录 + 索引持久化
```

## 四、⚠️ 验收标准（项目完成的定义）

```
⭐ 项目算完成，当且仅当：

□ FR-1 ~ FR-4 的"必须"项全部实现
□ 至少完成 E1（基线）+ E3（重排序）两个实验
□ ⭐ 指标代码有单元测试并通过
□ ⭐ 每个实验都报告了【基线】和【成本】
□ 测试集只用了一次
□ 有完整的实验报告（含局限说明）
□ 别人能按 README 复现主要结果
```

## 五、⭐ 明确不做（防止范围蔓延）

| 不做 | 原因 |
|---|---|
| ❌ 前端界面 | 本项目是实验台，不是产品 |
| ❌ 分布式部署 | 单机规模够用 |
| ❌ 大模型预训练 | 硬件不允许 |
| ❌ 全参微调 | 8GB 显存不允许 |
| ❌ 多语言支持 | 聚焦中文 |
| ❌ 实时服务 API | 加分项，非必须 |

> 🎯 **"明确不做"和"要做"一样重要**——它是**防止项目失控的第一道防线**。

---

**⭐ 一句话总结：**

> **必须项：能下载数据、能检索、能算对指标、能消融、能复现。**
