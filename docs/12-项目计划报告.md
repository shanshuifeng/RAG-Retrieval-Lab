### ⚠️ 当前最高优先级问题

**`mrr_at_k` 存在真实 bug —— 已于 2026-10-24 修复并量化影响**

```
位置：src/eval/metrics.py:84-93（修复前）
问题：rel = (str(x) for x in relevant)   ← 生成器，不是集合
后果：1) `if not rel` 永远为 False（生成器对象恒为真）
      2) 生成器只能消费一次，循环内 `d in rel` 会「吃掉」元素
      → 只有「第一个正例恰好排在第 1 位」时才算对，其余全部算成 0
```

**实测影响（dev 8,640 query，BM25 基线）**：

| 情形 | query 数 | 占比 | bug 下的结果 |
|---|---|---|---|
| 第一个正例在第 **1** 位 | 4,092 | 47.4% | ✅ 算对（1.0） |
| 第一个正例在第 **2–10** 位 | 2,295 | **26.6%** | ❌ 算成 0（应为 1/rank） |
| 前 10 无正例 | 2,253 | 26.1% | ✅ 碰巧算对（0.0） |

| 指标 | bug 版 | 正确值 | 误差 |
|---|---|---|---|
| **MRR@10** | 0.473611 | **0.562053** | **+0.0884（15.7% 相对）** |

**为什么危险**：它不报错、不崩溃，只是让指标**系统性偏低**，而
[docs/05](05-评测协议.md) 第一句话就是"如果指标算错，后面所有结论都是错的"。

**⚠️ 关键发现：第一版公式写错了，重合率只有 93.4%**

```
❌ 我最初写的：idf = ln(1 + (N - df + 0.5) / (df + 0.5))    ← Lucene 变体
✅ rank_bm25 实际：idf = log(N - df + 0.5) - log(df + 0.5)   ← 经典 Robertson
   + 负 IDF 处理：idf < 0 的词统一设为 eps = 0.25 × average_idf
```

这个差异**不报错**，只是让 6.6% 的 top-100 结果不同。
教训：**对齐第三方实现必须读源码，不能凭"常见公式"猜**（与项目纪律一致）。

**实际收益（实测）**：


### ⭐⭐ P5 结果：E2 是一个负面结果（Negative Result）

```
最优混合比最强单方法差 -12.96%（p<1e-300，CI 全在 0 以下）

⭐ 消融证据链（证明结论稳健，不是配置问题）：
  ① 权重扫描：最优 w_BM25=0（不混合），任何非零权重都单调变差
  ② 分数融合：0.7444 > RRF 0.7085，但仍 < 纯 D2 0.8139
  → 任何融合方式都不如直接用最强方法
```

**机理**：E1 的"互补性"（IoU 21.4%）是真的，但"结果不同"≠"融合有收益"。
当两方法质量悬殊（D2 是 BM25 的 1.53 倍）时，弱方法是噪声源，
RRF 等权会把 BM25 的伪高排名拉进前列，稀释 D2 的正确排序。

**⭐ 对 E3 的直接指导**：重排序的第一段用【纯 D2】，不用混合。
