## 一、主数据集：DuReader-retrieval

### 1.1 基本信息

| 项 | 内容 |
|---|---|
| **全称** | DuReader-Retrieval: A Large-scale Chinese Benchmark for Passage Retrieval from Web Search Engine |
| **来源** | 百度 |
| **论文** | [ACL EMNLP 2022](https://aclanthology.org/2022.emnlp-main.357/) |
| **任务** | 中文段落检索（Passage Retrieval） |
| **规模** | **97K queries / 890 万 unique passages** |
| **数据类型** | 真实搜索引擎用户日志 |
| **标注** | ⭐ 自带二元相关性标注（相关 / 不相关） |
| **许可** | 学术研究使用（详见官方说明） |

### 1.2 ⭐ 为什么选它

```
⭐⭐ 四个决定性优势：

① 国内直连，无需翻墙 ✅
    ModelScope 上有镜像，下载方便
        ↓
    对比：很多数据集只能从 Google Drive / HuggingFace 拿
         在国内极其痛苦

② 自带相关性标注 ✅
    · 不需要自己标注（标注成本极高）
    · 指标可客观计算
    · ⭐ 可与论文对比

③ 规模适中，可大可小 ✅
    · 可先用子集（10 万段落）跑通
    · 再上全量验证
    · ⭐ 8GB 显存 / 32GB 内存的机器够用

④ 中文原生 ✅
    · 不是翻译数据集（翻译会引入偏差）
    · 语料来自真实中文网页
```

### 1.3 ⚠️ 规模风险（必须正视）

```
⚠️ 890 万段落是什么概念？

    假设每段 200 字 → 约 17.8 亿字
    用 BGE-small 编码（~100MB 模型）：
        · CPU 编码速度 ~50 段落/秒
        · 890 万 / 50 = 178,000 秒 ≈ 【49 小时】⚠️
        · 加 GPU（RTX 4060）可能 ~500/秒 → 【5 小时】
        · 向量存储：890万 × 512维 × 4字节 ≈ 【18 GB】⚠️

        ↓
    ⭐ 结论：全量必须用 GPU + 分批处理，且要预留磁盘
```

### 1.4 ⭐⭐ 分阶段策略（关键决策）

| 阶段 | 语料规模 | 目的 | 可行性 |
|---|---|---|---|
| **阶段 1** | **1 万段落** | 跑通全流程、调试代码 | ⭐ 秒级，绝对可行 |
| **阶段 2** | **10 万段落** | 出初步对比结果 | ⭐ 几分钟，可行 |
| **阶段 3** | **100 万段落** | 验证规模效应 | ⚠️ 需 GPU，可行 |
| **阶段 4** | 890 万全量 | 复现论文 | ⚠️ 需数小时 + 18GB 磁盘 |

**⭐ 建议：本项目主线做到【阶段 2 或 3】，全量作为可选项。**

> 🎯 **这个策略本身就值得写进报告**——它体现了"先小规模验证，再扩展"的工程思维（呼应 Course 2 第 13.1 节的迭代开发）。

## 三、⭐ 统一数据格式

**无论用哪个来源，统一转换成以下格式**（保证后续代码不用改）：

### 3.1 语料库格式（JSONL）

```jsonl
{"id": "p_0000001", "text": "南昌大学是江西省唯一一所国家'双一流'建设高校……", "title": "南昌大学简介"}
{"id": "p_0000002", "text": "前湖校区位于南昌市红谷滩区……", "title": "校区介绍"}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | str | ⭐ **段落唯一标识**（用于计算指标） |
| `text` | str | 段落正文 |
| `title` | str | 标题（可选，部分任务会用） |

### 3.2 查询格式（JSONL）

```jsonl
{"qid": "q_0001", "query": "南昌大学有哪些重点学科？", "relevant_ids": ["p_0000001", "p_0000042"]}
{"qid": "q_0002", "query": "南昌大学前湖校区在哪？", "relevant_ids": ["p_0000002"]}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `qid` | str | 查询唯一标识 |
| `query` | str | 查询文本 |
| `relevant_ids` | list[str] | ⭐ **相关段落的 id 列表**（评测的核心） |

> ⚠️ **注意**：`relevant_ids` 可能是**空列表**（该 query 无标注相关段落）——
> **按评测协议第 4.5 条，这些 query 应在统计时过滤，并记录过滤数量。**

## 四、数据预处理规范

### 4.1 必须做的清洗

| # | 操作 | 理由 |
|---|---|---|
| **1** | **去除 HTML 标签** | 原始数据来自网页，含 `<div>` 等 |
| **2** | **去除多余空白** | 网页文本常有大量换行/空格 |
| **3** | **处理全角/半角** | 中文标点统一（可选） |
| **4** | **过滤过短段落** | 如 < 20 字，多半是噪声 |
| **5** | ⭐ **过滤过长段落** | 如 > 1000 字，需截断或分块 |
| **6** | **去重** | 网页内容常重复 |

### 4.2 ⚠️ 关于分块（Chunking）

**这是 E4 实验的核心变量，但基线阶段要固定策略。**

| 策略 | 做法 | 优缺点 |
|---|---|---|
| **A. 不切分** | 用数据集原生的 passage | ✅ 与论文可比 |
| **B. 固定长度** | 如 256 字，重叠 50 字 | ✅ 简单可控 |
| **C. 按段落** | 按 `\n\n` 切 | ✅ 语义完整 |
| **D. 语义分块** | 用嵌入相似度找边界 | ⚠️ 复杂，效果未必好 |

> ⭐ **基线阶段用 A（不切分）**——因为要与论文对比，**必须用原始 passage 定义**。
> **E4 才系统对比不同策略。**

## 五、数据集统计（M1 阶段要产出的）

**⭐ 下载后必须做的第一件事：统计数据并记录**

```python
# scripts/analyze_dataset.py 的产出内容
统计项：
  · 语料库段落数
  · 查询数
  · ⭐ 平均/中位数/最大 相关段落数
  · ⭐ 有多少 query 的相关段落数为 0（要被过滤）
  · 段落长度分布（均值、中位数、P95）
  · ⭐ 训练/验证/测试划分的实际数量
```

**产出格式：**

```json
{
  "corpus_passages": 100000,
  "queries_total": 86395,
  "queries_with_no_relevant": 1234,
  "queries_effective": 85161,
  "relevant_per_query": {"mean": 1.8, "median": 1, "max": 15},
  "passage_length": {"mean": 187, "median": 165, "p95": 420}
}
```

> ⚠️ **这些数字必须写进实验报告** —— 因为**指标值与数据分布强相关**，
> 不比数据分布就比指标，是无效对比。

## 六、数据集划分

### 6.1 ⭐ 划分原则

```
┌────────────────────────────────────────────────────────┐
│  ⚠️ 铁律：测试集【只用一次】                            │
│                                                        │
│   train（官方）→ 切出 dev（10%）→ 调参                  │
│   dev          → 选模型、调超参                          │
│   ⭐ test（官方）→ 只在最终报告时跑一次                   │
└────────────────────────────────────────────────────────┘
```

| 集合 | 来源 | 用途 |
|---|---|---|
| **train** | 官方 86,395 条 | 训练/微调（本项目主要是调参） |
| **dev** | 从 train 切 10% | ⭐ 调超参数 |
| **test** | 官方 2,000 条 | ⭐ **只跑一次，用于报告** |

### 6.2 ⚠️ 关于"语料库"的特殊性

```
⚠️ 检索任务的语料库【不划分】！

    训练集和测试集【共用同一个语料库】（890 万段落）
        ↓
    因为检索的任务就是"从全库里找"
        ↓
    所以：
    · 语料库 = 全量（或你选定的子集）
    · 划分只针对【query】
```
