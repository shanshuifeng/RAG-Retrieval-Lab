## 零、⭐ 本报告要回答什么

> **Q2：混合检索（RRF）比单方法有提升吗？**

**答案：没有。在本数据上，混合是【负优化】，且该结论经消融验证稳健。**

---

## 一、⭐ 为什么做这个实验（E1 提供的量化动机）

E1 实测发现一个看似支持混合的信号：

```
BM25(调优) 与 D1/BGE-small 的 Top-10 平均 IoU = 0.2143
  → 两方法的检索结果只有 21.4% 重合
  → 在 3,169 / 8,640（36.7%）的 query 上，两结果取并集能多命中相关文档
      ↓
  推测：两者互补，融合应该能提升
```

**E2 的任务就是验证这个推测是否成立。**

---

## 二、实验设置

### 2.1 方法

| 方法 | 说明 |
|---|---|
| **RRF** | `score(d) = Σ_i w_i / (k + rank_i(d))`，只用排名，免疫量纲差异 |
| 分数加权融合 | min-max 归一化后加权（消融对照，验证"只用排名"是否合适） |

> ⭐ 选 RRF 当主线的原因：BM25 分数与稠密余弦相似度**量纲完全不同**，
> 直接加权不可比；RRF 只用排名，天然规避（[docs/06](06-实验设计.md) §2.3）。

### 2.2 实验组（全部在 dev 上）

| 组 | 配置 |
|---|---|
| 单方法 | BM25(调优 k1=0.7) / D1(small) / D2(base) |
| RRF 等权 | 2 种组合 × k∈{20,40,60,80,100} = 10 组 |
| **RRF 加权** | 弱方法权重 w∈{0, 0.05, 0.1, 0.2, 0.3, 0.5, 1.0}（消融①） |
| 分数融合 | 排名倒数当分数（消融②） |

> 融合是纯排名计算，**零检索成本**（不重跑检索），17 秒跑完全部 10 组网格 + 消融。

---

## 三、⭐ 结果：混合是负优化

### 3.1 RRF 等权 + k 网格

| 组合 | 最优 k | nDCG@10 | Recall@10 |
|---|---|---|---|
| BM25(调优) + D1 | 20 | 0.6705 | 0.7780 |
| BM25(调优) + D2 | 20 | 0.7085 | 0.8226 |

**单方法基线**：

| 方法 | nDCG@10 | Recall@10 |
|---|---|---|
| BM25(调优) | 0.5305 | 0.6102 |
| D1/small | 0.7332 | 0.8151 |
| **D2/base** | **0.8139** | **0.8875** |

```
最优混合 nDCG@10 = 0.7085（BM25+D2, k=20）
最强单方法 nDCG@10 = 0.8139（D2）
        ↓
⭐ 混合比最强单方法还差 -12.96%
```

### 3.2 ⭐ 消融①：权重扫描——失败不是因为"权重没调好"

| w_BM25（弱） | w_D2（强） | nDCG@10 |
|---|---|---|
| **0.00** | 1.0 | **0.8139** ⭐（= 纯 D2） |
| 0.05 | 1.0 | 0.8126 |
| 0.10 | 1.0 | 0.8083 |
| 0.20 | 1.0 | 0.7961 |
| 0.50 | 1.0 | 0.7650 |
| 1.00 | 1.0 | 0.7085（等权） |

BM25+D1 组合同样单调：

| w_BM25 | nDCG@10 |
|---|---|
| **0.00** | **0.7332** ⭐（= 纯 D1） |
| 0.20 | 0.7279 |
| 0.50 | 0.7079 |
| 1.00 | 0.6705 |

```
⭐ 决定性证据：最优权重是 w_BM25 = 0 —— 即「不混合」
   给 BM25 任何非零权重，nDCG@10 都单调下降
   → 失败不是"等权没调好"，而是混合本身在这个组合上就不该做
```

### 3.3 消融②：分数融合也救不回

| 方法 | nDCG@10 | Recall@10 |
|---|---|---|
| RRF（最优） | 0.7085 | 0.8226 |
| 分数融合（排名倒数） | 0.7444 | 0.8526 |
| **纯 D2** | **0.8139** | **0.8875** |

> 分数融合比 RRF 好（0.7444 > 0.7085），但仍显著低于纯 D2（0.8139）。
> **任何融合方式都不如直接用最强的那个方法。**

### 3.4 ⭐ 显著性检验

| 对比 | 差值 | 相对 | p 值 | Cohen's d | 判定 |
|---|---|---|---|---|---|
| 混合 vs BM25(调优) | +0.1779 | +33.5% | <1e-300 | 0.799 | 混合赢弱方法 |
| **混合 vs D2/base** | **−0.1055** | **−12.96%** | **<1e-300** | **−0.479** | **⭐ 混合输给强方法** |

混合 vs D2：95% CI = [−0.110, −0.101] 全在 0 以下 → **显著为负**。
逐 query：变好 992 / 变差 3,912。

## 四、⭐ 为什么混合反而变差？——机理分析

E1 的"互补性"信号（IoU 21.4%）是真的，但它**不等于**"融合有收益"：

```
误解：IoU 低 → 两方法不同 → 互补 → 融合提升

实际：
  ① IoU 低只说明"结果不同"，不说明"不同是有价值的"
     BM25 的 Top-10 里有大量 D2 没召回的【不相关】段落

  ② 并集多命中 ≠ 排序更好
     36.7% 的 query 上并集多命中，但 RRF 会把 BM25 的高排名
     错误结果（BM25 认为很相关、实际不相关）拉进融合前列

  ③ ⭐ 核心：当两方法质量悬殊时，弱方法成为噪声源
     D2 的 nDCG 是 BM25 的 1.53 倍
     BM25 的 Top-1 命中里，很多 D2 根本不认为相关
     RRF 等权后，这些"伪高排名"稀释了 D2 的正确排序
```

**一句话**：互补性融合的前提是【两方法质量相当】。当一方显著更强时，
混合是把强者的正确排序稀释上弱者的噪声。

## 五、⭐ 结论（Q2 的答案）

| 问题 | 答案 |
|---|---|
| 混合检索（RRF）有提升吗？ | **没有，反而显著变差（-12.96%，d=-0.479）** |
| 是权重没调好吗？ | 不是——权重扫描显示最优是 w_弱=0（不混合） |
| 是融合方式不对吗？ | 不是——分数融合同样输给纯 D2 |
| E1 的互补性信号错了吗？ | 没错，但"结果不同"≠"融合有收益" |

### ⭐ 这个负面结果的价值

```
① 它推翻了一个看似合理的推测（IoU 低 → 互补 → 融合提升）
② 它给出了一个可复用的判断准则：
   "当两方法质量悬殊（nDCG 差 >50%）时，RRF 融合是负优化"
③ 它直接决定了 E3 的设计：重排序的第一段应该用【纯 D2】，不是混合
```

> ⚠️ **2026-10-25 审查修正：上述第 ② 条准则已被补测【证伪】**
>
> 补测了质量接近的组合（dev，`results/2026-10-25_221613_audit_close_quality_hybrid.json`）：
>
> | 组合 | 质量比 | Top-10 IoU | 最优混合 vs 最强单方法 |
> |---|---|---|---|
> | BM25 × D1 | 1.382× | 0.2143 | **-6.15%** |
> | BM25 × D2 | 1.534× | 0.2015 | **-9.73%** |
> | **D1 × D2** | **1.110×（接近）** | 0.4136 | **-2.86%** |
>
> ```
> ⭐ 质量只差 11% 时，混合依然下降 →「质量悬殊」不是失败的原因
> ⭐ 三个组合的最优 K 都落在最小档（5–10），最优权重都是 w_弱 = 0
>     → 不是参数没调好，是融合本身在这个设定下不该做
> ```
>
> **更可能的真实机理**：RRF 按**排名**加权，无法识别"弱方法的第 1 名其实是错的"。
> 即使弱方法只弱 11%，它的 top-10 里仍有大量错误段落，
> 融合把这些错误排名拉进前列，稀释了强者的正确排序。
> → 真正的门槛是**弱方法的 precision@10**，而不是两方法的质量差。
>
> ⭐ **好消息**：「混合在本数据上是负优化」这个**主结论更强了**
> ——从单一组合扩展到三种，并排除了"质量差"这个干扰因素。
> ⚠️ 但原先给出的**机理解释是错的**，已在此更正。
>
> 详见 [docs/18-项目审查报告](18-项目审查报告.md) M4。

## 六、⚠️ 本结论的有效边界

| 边界 | 说明 |
|---|---|
| **数据** | 本结论基于 DuReader dev（10 万段）。在两方法质量接近的其他数据集上，混合仍可能有效——本结论**不能外推**为"RRF 无用" |
| **方法** | 只测了 RRF 与排名分数融合。未测 learned fusion（学习型融合），那需要训练 |
| **组合** | 只测了 BM25×稠密。未测 稠密×稠密、BM25×BM25（不同分词）等组合 |
| **质量差** | 本结论的前提是"两方法质量悬殊"。质量相当时结论可能反转 |

> ⭐ 引用本结论时必须带这些边界，否则会误导为"混合检索没用"。
